# BeetleBoard Example Firmware

Comprehensive firmware and modular driver examples for **BeetleBoard**, an ESP32-C6 powered beetleweight battlebot flight & motor control board designed by [avycado13](https://github.com/avycado13).

---

## 📋 Hardware Pinout & Architecture

Based directly on the `BeetleBoard.kicad_sch`, `power.kicad_sch`, and `imu.kicad_sch` schematics:

| Schematic Net | XIAO Pin | ESP32-C6 GPIO | Direction | Function & Hardware Circuitry |
|:---|:---:|:---:|:---:|:---|
| `VBAT_SNS` | **D0** | **GPIO 0** | Input (ADC1_CH0) | Battery voltage sense divider: $R_{10} = 120\text{ k}\Omega$, $R_9 = 33.2\text{ k}\Omega$, $C_7 = 100\text{ nF}$ filter |
| `BUCK_EN` | **D1** | **GPIO 1** | Output | Enable pin (Pin 5) of TPS563200 3A 5V Buck Regulator (active-HIGH) |
| `ESC_A` | **D2** | **GPIO 2** | Output (PWM) | ESC Header **J2** (Pin 1 Signal), 33k pulldown $R_3$, ESD diode $D_2$ |
| `ESC_B` | **D3** | **GPIO 21** | Output (PWM) | ESC Header **J3** (Pin 1 Signal), 33k pulldown $R_2$, ESD diode $D_3$ |
| `ESC_C` | **D4** | **GPIO 22** | Output (PWM) | ESC Header **J4** (Pin 1 Signal), 33k pulldown $R_1$, ESD diode $D_4$ |
| `ESC_D` | **MTDI** | **GPIO 5** | Output (PWM) | ESC Header **J5** (Pin 1 Signal), 33k pulldown $R_4$, ESD diode $D_5$ |
| `ESC_E` | **MTDO** | **GPIO 7** | Output (PWM) | ESC Header **J6** (Pin 1 Signal), 33k pulldown $R_5$, ESD diode $D_7$ |
| `ESC_F` | **MTCK** | **GPIO 6** | Output (PWM) | ESC Header **J7** (Pin 1 Signal), 33k pulldown $R_6$, ESD diode $D_6$ |
| `SPI_CS` | **D5** | **GPIO 23** | Output | Chip Select for LSM6DSV320XTR IMU (Pin 12 CS) |
| `XIAO_TX` | **D6** | **GPIO 16** | Output (UART TX) | J18 ELRS Receiver Header (Pin 1 RX on receiver) |
| `XIAO_RX` | **D7** | **GPIO 17** | Input (UART RX) | J18 ELRS Receiver Header (Pin 2 TX on receiver) |
| `SPI_SCK` | **D8** | **GPIO 19** | Output (SPI CLK) | LSM6DSV320XTR IMU (Pin 13 SCK), 100k pulldown $R_{14}$ |
| `SPI_MISO` | **D9** | **GPIO 20** | Input (SPI MISO) | LSM6DSV320XTR IMU (Pin 1 SDO), 33k pullup $R_{13}$ |
| `SPI_MOSI` | **D10** | **GPIO 18** | Output (SPI MOSI) | LSM6DSV320XTR IMU (Pin 14 SDI) |
| *LED* | Internal | **GPIO 15** | Output | XIAO ESP32-C6 onboard user LED (Active-LOW: LOW=ON, HIGH=OFF) |
| `+5V` | **5V** | VBUS Rail | Power | Generated by TPS563200 buck regulator from battery, powers ESCs & ELRS |
| `+3V3` | **3V3** | 3.3V Rail | Power | Generated by XIAO onboard LDO regulator, powers LSM6DSV320XTR IMU |

> [!NOTE]
> On the PCB, ESC headers **J16** (`ESC_G`) and **J17** (`ESC_H`) include ESD diodes and pulldown resistors for expansion or passthrough, but their signal pins are unrouted to the MCU on this revision.

## ⚡ Subsystem Details

### 1. Battery Voltage Sensing & Software UVLO
- **Circuit**: Voltage divider with $R_{10} = 120\text{ k}\Omega$ (top) and $R_9 = 33.2\text{ k}\Omega$ (bottom).
  $$\text{Ratio} = \frac{33.2}{120 + 33.2} = \frac{33.2}{153.2} \approx 0.21671$$
  $$V_{\text{BAT}} = V_{\text{pin}} \times \frac{153.2}{33.2} \approx V_{\text{pin}} \times 4.61446$$
- **Software Undervoltage Lockout (UVLO)**:
  - Automatically identifies battery cell count (2S: ~7.4V, 3S: ~11.1V, 4S: ~14.8V).
  - Continuous exponential moving average filter rejects transient motor punch-out voltage sag.
  - If average cell voltage stays below **3.30V** for $>1.5\text{ s}$, the MCU pulls `BUCK_EN` (GPIO 1) **LOW**, disabling the TPS563200 5V buck regulator to save the LiPo pack from over-discharge damage.

### 2. 6-Channel ESC PWM Generator
- Channels ESC A through F are driven by the ESP32-C6 LEDC hardware PWM generator at **50 Hz** (20 ms period) with **14-bit** resolution.
- Supports both standard unidirectional throttle ($1000\mu\text{s}$ to $2000\mu\text{s}$) and bidirectional drive ($1000\mu\text{s}$ reverse, $1500\mu\text{s}$ neutral, $2000\mu\text{s}$ forward).
- Includes **software arming safety** and **instant emergency stop**.

### 3. LSM6DSV320XTR 6-Axis High-G IMU
- High-g 6-axis IMU rated up to **$\pm 320\text{ g}$** and **$\pm 4000\text{ dps}$**, specifically designed to withstand violent battlebot impacts and meltybrain spin rates.
- Connected via a dedicated 4-wire SPI bus at 4 MHz (Mode 0).
- Verifies identity via `WHO_AM_I` (`0x73`), configures 120 Hz ODR, and streams calibrated acceleration ($g$), angular rates ($\text{dps}$), and rotational spin rate ($\text{RPM}$).

### 4. ExpressLRS (ELRS) / CRSF Receiver
- Standard 4-pin header for BetaFPV Lite, Radiomaster, or Happymodel ELRS receivers.
- Communicates over UART (Serial1) at **420,000 baud** using the standard CRSF protocol.
- Includes full 16-channel 11-bit packet unpacking, Link Quality (LQ), RSSI telemetry, and failsafe detection ($>250\text{ ms}$ packet timeout).

## 🚀 Building & Flashing

### Option A: Using PlatformIO (Recommended)

1. Open VS Code with the **PlatformIO IDE** extension installed.
2. Open the `firmware/` folder (`File -> Open Folder...`).
3. Connect your BeetleBoard via USB-C.
4. Click **Build** (`✓`) or **Upload** (`→`) on the PlatformIO status bar.
5. Open the Serial Monitor at **115,200 baud**.

Or via CLI:
```bash
cd firmware
pio run --target upload
pio device monitor -b 115200
```

### Option B: Using Arduino IDE

1. Install the **esp32** board package by Espressif (`Tools -> Board -> Boards Manager -> esp32` version 3.0.0 or newer).
2. Select Board: **"Seeed Studio XIAO ESP32C6"** (or **"ESP32C6 Dev Module"**).
3. Set the following under the `Tools` menu:
   - **USB CDC On Boot**: `"Enabled"`
   - **Upload Mode**: `"UART0 / Hardware CDC"`
   - **Flash Size**: `"4MB"`
4. Open `firmware/src/main.cpp` (or any `.ino` sketch under `firmware/examples/`).
5. Click **Upload** and open the Serial Monitor at 115200 baud.

## 💻 Interactive Serial Console

The primary firmware (`main.cpp`) includes a built-in USB Serial command interface:

| Key | Action |
|:---:|:---|
| `s` | **Print full system status** (Battery V, LiPo cells, 5V buck state, ESC PWM, IMU, ELRS) |
| `b` | **Toggle 5V Buck Regulator** (Force enable/disable TPS563200 via `BUCK_EN` GPIO 1) |
| `a` | **Toggle Software Arming** (Arm/Disarm motor outputs) |
| `m` | **Motor Bench Sweep Test** (Gentle 3-second throttle ramp on ESC A) |
| `t` | **Stream IMU Telemetry** (Real-time Accel X/Y/Z, Gyro X/Y/Z, and Yaw RPM) |
| `r` | **Stream ELRS RC Channels** (Real-time stick positions, Link Quality, RSSI) |
| `v` | **Stream Battery Voltage** (Continuous voltage & UVLO status) |
| `u` | **Reset UVLO Cutoff** (Clear undervoltage trip and re-enable 5V rail) |
| `h` / `?` | **Show Help Menu** |

## 🛡️ Safety Guidelines for Battlebot Testing

> [!CAUTION]
> **ALWAYS REMOVE ALL WEAPONS AND PROPELLERS BEFORE BENCH TESTING.**
> 1. Ensure the board is disarmed before powering on the battery.
> 2. Keep the robot propped up on a stand so drive wheels cannot contact the bench surface.
> 3. Verify failsafe operation by turning off your transmitter while motors are idling; all ESC outputs should immediately revert to $1000\mu\text{s}$ (stopped).
